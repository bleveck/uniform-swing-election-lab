# Uniform swing election-night lab

A small R/Shiny teaching demo. Incoming results from ten early House races produce an equal-weight estimate of the change in Democratic two-party vote share. Applying that change everywhere produces an illustrative House seat count. This is intentionally a classroom experiment, not a serious forecast.

[Open the hosted app](https://01a18994-b6cc-bced-bec2-7a672ba20d82.share.connect.posit.cloud/) · [Source and automated checks](https://github.com/bleveck/uniform-swing-election-lab)

## Run it

From this project directory, in R or RStudio:

```r
source("scripts/install.R")  # installs only missing dependencies
shiny::runApp(".")
```

Or from a terminal:

```sh
Rscript -e 'shiny::runApp(".", host="127.0.0.1", port=3838)'
```

The app opens on **Start here**, a four-part introduction framed around a political scientist who slept through the election cycle. The default reference is the preceding **presidential vote**, with a separately fitted Bayesian prior. The previous House vote remains an option. Historical charts and synthetic examples work without network access. **Election-night lab** opens in Synthetic replay mode. Each reference has its own invented returns generated on the appropriate map: presidential on 2026 lines, House on 2024 lines. These are teaching scenarios, not historical election-night data or predictions of 2026 outcomes.

The introduction includes an annotated 2010 uniform-swing scatter plot and comparisons for 2006, 2010, 2014, and 2018; a time plot and histogram of historical midterm means; a single-cycle histogram built from stacked district labels; a reporting-order experiment with fixed final votes; and a progressive raw/Bayesian replay. The last example can carry its snapshot into the full lab. Historical panels use the existing audited matched-district sample and its exclusions. The reporting-order example and the 2026 replay are explicitly synthetic.

Section 3 also includes **CA-13’s actual 2024 count**, added alongside the synthetic example: 31 California Voter Foundation snapshots from November 5 to December 5, with a replay slider and views of the vote lead or Democratic share. The last totals match the certified Gray 105,554 / Duarte 105,367 result. Recorded times retain the source clock without an assumed time zone. The percentage of final votes is retrospective, rather than a percentage-counted estimate available at the time. Source links and a CSV download are in the app.

A short console-only version needs only base R:

```sh
Rscript scripts/demo.R
```

The final presidential-reference snapshot gives approximately **D +3.00 percentage points relative to the presidential vote**, implying **221 D / 214 R seats on the 2026 map** in raw mode. The House-reference scenario gives 231 D / 204 R on the 2024 map. These are illustrations generated by the supplied scenarios.

## What is implemented

- A four-part **Start here** introduction, with historical charts, a searchable district-label histogram, an interactive reporting-order example, and a replay linked to the full lab.
- Official 2024 House baseline for all 435 voting seats, rebuilt from the House Clerk's report. At zero swing it reproduces **215 D / 220 R**.
- Synthetic replay of KY-06; VA-01, VA-02, VA-05; NC-01, NC-11; OH-07, OH-09, OH-10, OH-15.
- Working official-feed readers for **Virginia JSON, North Carolina ZIP/TSV, and Ohio XML**.
- A manual CSV fallback, including a KY-06 supplement in live mode.
- Individual district changes, the average, a swing-to-seats curve, a 435-seat graphic, inclusion decisions, and downloadable calculations.
- Two explicit baselines: **2024 House on the old map**, or **2024 president on the 2026 map**.
- An optional **Bayesian Normal-prior estimate**, fitted to historical midterms, with raw/prior/posterior comparisons and analytic arithmetic.
- A redistricting comparison using The Downballot's exact 2024 presidential totals on both maps.
- Date/schema/input checks, exclusion of test/pre-election feeds, and retention of a provider's last good snapshot after a fetch error.

Only House races enter the estimator. The Senate and governor contests in the reference post are outside the model.

CSV required columns:

## Redistricting and the two baselines

**House baseline:** compares 2026 House returns with actual 2024 House results. The national projection is explicitly on the **2024 map**. For live/CSV estimation, every district in the nine states with new maps is conservatively excluded. This includes unchanged individual districts within those states; there is no claim that every district in the state changed. The synthetic replay is generated on the old map and includes all ten districts.

**Presidential baseline (default):** uses The Downballot's 2024 presidential returns recalculated on **2026 district boundaries** for all 435 seats. This supports the full watchlist on consistent geography. The inferred change is **2026 House share minus 2024 presidential share**, a cross-office difference rather than a House-to-House swing. It supports both raw and Bayesian estimates, with its own historical prior and current-map replay. Changing results source preserves the selected reference.

Cook's updated PVI can describe partisan lean, but its 2026 scores combine the 2020 and 2024 presidential elections. For a one-election classroom comparison, directly reaggregated 2024 votes are easier to explain. A further approximation would be:

```text
adjusted House baseline = 2024 House D share
                       + (2024 presidential D share on new map
                          − 2024 presidential D share on old map)
```

That carries the old district's House-versus-president residual into the new district. It can be misleading when district numbers survive but their electorates and incumbents change substantially, and it does not solve uncontested 2024 races. It is documented here but not silently applied in the app.

The Census lists nine states with new 2026 boundaries: AL, CA, FL, LA, NC, OH, TN, TX, and UT. Missouri's proposed map was reversed; the build script explicitly restores its 2024-map presidential totals. See [the source research](docs/data_sources.md).

## The model

For each eligible district, compute `current D / (D + R) − baseline D share`. Average those differences **equally across districts**, then add the result to every baseline share. A +3 pp share shift is a +6 pp D-minus-R margin shift. Projected shares are clipped to [0, 1]; exact 50/50 ties remain unresolved.

The minimum-vote threshold defaults to 1,000 D+R votes. It screens very small batches but does **not** correct reporting bias. Students can exclude individual districts and inspect the resulting change. In raw mode, no eligible districts means no estimate. Bayesian mode instead shows the historical prior and explicitly labels it **prior only**.

In House mode, 38 one-party/same-party contests are held at their actual 2024 winner rather than imputing an opponent. The parser combines fusion ballot lines with their candidate, recognizes Minnesota DFL candidates as Democrats, and records missing official votes in unopposed FL-20 and OK-03 as missing. Maine uses the final ranked-choice tally printed by the Clerk; Alaska uses the printed first-choice totals, including both Democratic candidates. Such simplifications limit the national thought experiment.

Early reporting is selective by geography and ballot method, this watchlist is not random, and candidate/turnout effects differ. The Bayesian interval is conditional on the displayed model and noise assumptions; the app supplies no calibrated forecast interval or win probability. The seat curve shows sensitivity to the common shift. Actual current returns are used to learn the shift, not to lock individual seats into the projection.

## Bayesian option

Select **Bayesian: history + results** under “Estimate used for seats.” The app compares the raw and posterior means and uses the selected method for the seat count and seat graphic. The **Bayesian update** tab shows the historical prior, current-data likelihood, posterior density, historical election sample, and the actual numerical update. Raw mode remains the default.

Each reference has a separately fitted Normal prior for 2026 Democratic performance:

```text
House minus president (default): Normal(mean = +7.165 pp, SD = 5.688 pp)
House minus previous House:      Normal(mean = +4.201 pp, SD = 2.157 pp)
```

The default uses **14 midterms, 1954–2018**. Gary Jacobson’s [replication dataset](https://doi.org/10.7910/DVN/29559) provides two-party House and presidential shares through 2014; [The Downballot / ccesMRPprep](https://www.shirokuriwaki.com/ccesMRPprep/reference/cd_info.html) supplies 2016 presidential shares on 2018 lines for the extension. The codebook confirms that `dpres` is major-party presidential share and refers to the preceding election in midterms. Unopposed or missing House shares and Jacobson’s redrawn-district flags are excluded. Presidential shares are absent for 1946 and 1950. Modern data are available for 2022, but the post-census exclusion is retained, so 2018 is the last included midterm.

The House alternative uses **16 midterms, 1946–2018**, with its original conservative boundary and major-party-contest screens. Both priors reverse Democratic performance under Democratic presidents so positive historical values mean performance toward the out-party. Both exclude post-census midterms **1962, 1982, 2002, and 2022**.

Each election contributes one mean with equal election weights. The prior SD is the **between-election standard deviation**, not the standard error of the historical mean. Negative observations remain. Cross-office performance includes ticket splitting and differences between presidential and House candidates; it is a different quantity from the change in House votes. For example, 1978 is negative toward the out-party in the presidential-reference sample, even though the House-to-House movement went against the president’s party.

The analytic update uses:

```text
raw average | theta ~ Normal(theta, s^2)
s^2 = historical district noise^2 / included districts
data weight w = prior variance / (prior variance + s^2)
posterior mean = (1 - w) * prior mean + w * raw average
posterior variance = 1 / (1 / prior variance + 1 / s^2)
```

Pooled historical district residual SD is **10.889 pp** for the presidential reference and **7.073 pp** for the House reference. District deviations are independent conditional on the common shift, with a common residual variance. This Normal empirical-Bayes teaching model treats fitted parameters as fixed.

At presidential replay snapshot 6, the raw mean is **+3.103 pp** and the posterior is **+4.192 pp**, with about **27% history and 73% current-data weight**. Its model-conditional SD is 2.946 pp. The House alternative gives +3.672 pp at its snapshot 6. At zero observations each posterior equals its own prior. More districts reduce historical weight; additional cumulative reports from the same districts do not add independent observations.

Both references support Bayesian updating. Selecting a reference switches its historical sample, residual scale, replay, and projection map together. The introduction has the same reference selector and carries its choice into the lab.

For a small console example:

```sh
Rscript scripts/bayes_demo.R
```

See [the full Bayesian derivation and data audit](docs/bayesian.md).

Source: [bleveck/uniform-swing-election-lab](https://github.com/bleveck/uniform-swing-election-lab). [Automated checks](https://github.com/bleveck/uniform-swing-election-lab/actions) validate each update before advancing the publishing branch.

Published to Connect Cloud on October 29, 2026. The public introduction, CA-13 replay, both Bayesian references, and CSV download were checked in a fresh browser session. Direct requests from Posit fetched North Carolina successfully, but Virginia and Ohio returned HTTP 403; the same feed code succeeded locally for all three states. **Shared laptop snapshots** provides the common data path for the hosted app. See [the collector guide](docs/collector.md) and [deployment guide](docs/deployment.md).

The publishing setup uses a public GitHub repository, `manifest.json`, and a checked publishing branch. The manifest pins R 4.5.2 and the 47 runtime packages, and includes only the 20 files needed to run the app. Raw source archives, rebuild scripts, tests, and documentation remain available in GitHub.

On every push to `main`, GitHub Actions installs the pinned runtime packages, checks the deployment bundle, and runs the model, data, parser, and Shiny tests. Only a successful run advances **`codex/publish`**, the branch Connect Cloud should watch. Pull requests run the same checks without publishing. No Posit API key is needed in GitHub.

In Connect Cloud, choose **Publish → Shiny**, select this repository, set Branch to **`codex/publish`**, choose **`app.R`** as the Primary file, and leave **Automatically publish on push** enabled. First-time setup requires signing in and connecting the Posit GitHub App. See [the deployment guide](docs/deployment.md) for the exact sequence and update commands.

Before pushing changes to app code, runtime data, or packages:

```sh
Rscript scripts/write_manifest.R
Rscript scripts/check_deployment.R
Rscript tests/run_tests.R
```

Commit the updated manifest with the change. Documentation-only changes do not require regenerating it. `rsconnect` is needed to generate the manifest, but is not a hosted-app dependency. The deployment check loads a temporary copy containing only the bundled files, catching missing-file dependencies before publication.
